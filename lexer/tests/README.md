# Тесты учебного лексера

Положительные файлы проверяют ключевые слова, идентификаторы, числовые и символьные литералы, обычные и интерполированные строки, комментарии и поддерживаемые операторы.

В строках и символах используются только `\n`, `\t`, `\v`, `\\`, `\"` и `\'`. Продолжение строки через обратную косую черту перед физическим переводом строки проверяется отдельно в строковых примерах.

Файлы `lexer_invalid_*` содержат намеренные ошибки. Скрипт ожидает код завершения `1` и конкретные сообщения лексера. Директивы и идентификаторы в обратных кавычках не поддерживаются и проверяются как ошибочный ввод.

Это лексические тесты, а не проверка синтаксической или семантической корректности F#. Например, файл ключевых слов содержит отдельные лексемы, а диапазоны типов целых чисел с суффиксами относятся к последующей семантической проверке.

## Запуск

Перед запуском нужно заново сгенерировать `lex.yy.cpp` из текущего `.l` и собрать исполняемый файл лексера. Скрипт тестов этого не делает.

Из корня проекта:

```powershell
.\lexer\tests\run_tests.ps1
```

По умолчанию используется `x64\Debug\fsharp-compiler.exe`. Другой путь можно указать явно:

```powershell
.\lexer\tests\run_tests.ps1 -LexerPath ".\x64\Release\fsharp-compiler.exe"
```

Также можно использовать `lexer\tests\run_tests.cmd`, который передаёт аргументы скрипту PowerShell.

Результаты записываются в `lexer\tests\test_report.txt`. Путь отчёта можно изменить параметром `-ReportPath`. Старый отчёт не обновляется до следующего запуска тестов.

Скрипт читает stdout и stderr целиком и проверяет имена токенов, выбранные значения литералов и диагностические сообщения. Для комментариев, операторов и ключевых слов проверяется порядок токенов без переводов строк. Новые случаи интерполяции сверяются по полному потоку токенов и значений.

Проверяются слитные формы с `!` и отдельный оператор, логические значения `1` и `0`, три уровня интерполяции, фигурные скобки в записях и комментариях, граница `uint64`, переполнение и слишком малые значения вещественных чисел. Большие `bigint` и точные `decimal` сохраняют исходную точность.
