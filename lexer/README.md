## 1.1. Перечень ключевых слов языка

### Обычные ключевые слова `ident-keyword`

Обычное ключевое слово внешне удовлетворяет форме идентификатора, но всегда распознаётся как зарезервированный токен. Правила ключевых слов должны располагаться перед общим правилом идентификатора либо найденный идентификатор должен проверяться по таблице ключевых слов.

| Лексема | Токен | Подробное назначение |
|---|---|---|
| `abstract` | `KW_ABSTRACT` | Объявляет абстрактный член без реализации либо виртуальный член с реализацией по умолчанию. |
| `and` | `KW_AND` | Связывает взаимно рекурсивные определения, несколько объявлений типов, дополнительные ограничения типов; используется и в ряде составных объявлений членов. |
| `as` | `KW_AS` | Присваивает имя всему шаблону или текущему объекту класса. |
| `assert` | `KW_ASSERT` | Создаёт проверку логического выражения во время выполнения/отладки. |
| `base` | `KW_BASE` | Обозначает объект базового класса. |
| `begin` | `KW_BEGIN` | Начинает блок в подробном (verbose) синтаксисе. |
| `class` | `KW_CLASS` | Начинает явное описание класса в подробном синтаксисе. |
| `const` | `KW_CONST` | Используется в ограниченных специальных контекстах, в частности типизированными провайдерами для константного параметра типа. В актуальной формальной спецификации входит в `ident-keyword`. |
| `default` | `KW_DEFAULT` | Задаёт реализацию по умолчанию для ранее объявленного абстрактного члена. |
| `delegate` | `KW_DELEGATE` | Объявляет тип делегата .NET. |
| `do` | `KW_DO` | Выполняет выражение ради побочного эффекта; входит в циклы и computation expressions. |
| `done` | `KW_DONE` | Завершает блок цикла в подробном синтаксисе. |
| `downcast` | `KW_DOWNCAST` | Выполняет явное приведение к более производному типу. |
| `downto` | `KW_DOWNTO` | Задаёт убывающий диапазон счётчика цикла `for`. |

| `exception` | `KW_EXCEPTION` | Объявляет новый тип исключения F#. |
| `extern` | `KW_EXTERN` | Объявляет внешний член или функцию, обычно для межъязыкового/неуправляемого взаимодействия. |
| `false` | `BOOL_FALSE` | Логический литерал ложного значения. Хотя формально это ключевое слово, лексер может возвращать отдельный токен логической константы. |
| `finally` | `KW_FINALLY` | Вводит блок, который выполняется при завершении `try` независимо от результата. |

| `namespace` | `KW_NAMESPACE` | Объявляет пространство имён. |
| `new` | `KW_NEW` | Объявляет конструктор либо явно создаёт объект. |

| `of` | `KW_OF` | Отделяет имя случая discriminated union/исключения от хранимых данных; применяется и в ряде типовых конструкций. |
| `open` | `KW_OPEN` | Делает содержимое пространства имён или модуля доступным без полного квалифицированного имени. |
| `or` | `KW_OR` | Ключевое слово совместимости ML; встречается в составных грамматических формах. Логическое ИЛИ в обычном коде записывается `||`. |
| `override` | `KW_OVERRIDE` | Переопределяет виртуальный или абстрактный член базового типа. |

| `upcast` | `KW_UPCAST` | Выполняет явное приведение к базовому типу. |

| `yield` | `KW_YIELD` | Производит элемент списка, массива, последовательности или computation expression. |

### Составные символические ключевые слова computation expressions

Лексически это самостоятельные многосимвольные токены, а не обычное ключевое слово плюс отдельно стоящий `!`. Их следует распознавать раньше обычных `let`, `use`, `do`, `yield`, `return`, `match` и `!`.

| Лексема | Токен | Назначение |
|---|---|---|
| `let!` | `KW_LET_BANG` | Связывает результат вычисления внутри computation expression. |
| `use!` | `KW_USE_BANG` | Связывает вычисляемый ресурс и организует его освобождение. |
| `do!` | `KW_DO_BANG` | Выполняет вложенное вычисление без связывания результата. |
| `yield!` | `KW_YIELD_BANG` | Передаёт наружу все элементы вложенного вычисления/последовательности. |
| `return!` | `KW_RETURN_BANG` | Возвращает результат вложенного вычисления без дополнительного оборачивания. |
| `match!` | `KW_MATCH_BANG` | Вычисляет выражение в computation expression и сразу сопоставляет его результат с образцами. |

### Контекстное ключевое слово

| Лексема | Первичный токен | Назначение и особенность |
|---|---|---|
| `select` | `IDENTIFIER` | Действует как ключевое слово только внутри query expression. На чисто лексическом этапе обычно остаётся идентификатором; контекст устанавливает синтаксический анализатор. |

### Слова, зарезервированные для будущего расширения

Эти последовательности нельзя безусловно принимать как пользовательские идентификаторы. Они не обязаны иметь действующую семантику, но лексер должен уметь сообщить «зарезервированное слово».

| Зарезервированные лексемы | Токен | Описание |
|---|---|---|
| `break`, `checked`, `component`, `constraint` | `RESERVED_KEYWORD` | Зарезервированы для возможного будущего синтаксиса F#. |
| `continue`, `fori`, `include` | `RESERVED_KEYWORD` | Зарезервированы; не должны использоваться как обычные имена без экранирования двойными обратными апострофами. |
| `mixin`, `parallel`, `params`, `process`, `protected`, `pure` | `RESERVED_KEYWORD` | Зарезервированы формальной спецификацией для будущего расширения. |
| `sealed`, `tailcall`, `trait`, `virtual` | `RESERVED_KEYWORD` | Зарезервированы формальной спецификацией для будущего расширения. |

> Некоторые страницы Microsoft Learn содержат исторический список, включающий `event` и `external` и не включающий `fori`/`params`. Для реализации лексера приоритетнее актуальная формальная глава **Lexical Analysis**, где приведён список выше. `const` в этой спецификации уже является обычным `ident-keyword`.

### Зарезервированные слова совместимости с OCaml/ML

| Лексемы | Токен | Описание |
|---|---|---|
| `asr`, `land`, `lor`, `lsl`, `lsr`, `lxor`, `mod` | `RESERVED_ML_KEYWORD` | Зарезервированы из-за совместимости с OCaml/ML. При специальном режиме совместимости компилятора часть таких слов может обрабатываться иначе. |
| `sig` | `KW_SIG` | Исторически относится к ML-совместимому набору, но формальная лексическая грамматика F# одновременно включает его в `ident-keyword`; поэтому в лексере ему лучше назначить отдельный ключевой токен. |

### Слова, которые больше не зарезервированы

| Лексемы | Как распознавать | Описание |
|---|---|---|
| `atomic`, `constructor`, `eager`, `functor`, `measure`, `method`, `object`, `recursive`, `volatile` | `IDENTIFIER` | Ранее резервировались, но в современном F# разрешены как обычные идентификаторы. Их нельзя ошибочно помещать в таблицу действующих ключевых слов. |

### Важные слова, которые лексически не являются ключевыми

| Текст | Как распознавать | Причина |
|---|---|---|
| `not` | `IDENTIFIER` | Это стандартная функция логического отрицания, а не зарезервированное слово. Синтаксически часто выглядит как префиксный оператор. |
| `infinity`, `infinityf` | `IDENTIFIER` | Обозначают стандартные значения бесконечности, но формальная лексическая грамматика распознаёт их как идентификаторы, не как числовые токены. Знак `-`/`+` является отдельным оператором. |
| `nan`, `nanf` | `IDENTIFIER` | Стандартные значения «не число» предоставляются окружением/библиотекой и не образуют отдельный числовой токен формальной грамматики. |

## 1.2. Правила описания имён классов, функций и переменных

Лексически имена классов, типов, функций, параметров, переменных, членов, модулей и пространств имён относятся к одному классу **идентификаторов**. Их роль определяется синтаксическим контекстом.

### Символьные классы обычного идентификатора

| Элемент | Формальное содержание | Пояснение |
|---|---|---|
| `digit-char` | `[0-9]` | Десятичная цифра. |
| `letter-char` | Unicode-категории `Lu`, `Ll`, `Lt`, `Lm`, `Lo`, `Nl` | Заглавные, строчные, титульные, модифицирующие и прочие буквы, а также буквенные числа Unicode. |
| `connecting-char` | Unicode-категория `Pc` | Соединительные знаки, включая `_` и другие допустимые Unicode-символы этой категории. |
| `combining-char` | Unicode-категории `Mn`, `Mc` | Комбинируемые символы без занимаемой позиции и с занимаемой позицией. |
| `formatting-char` | Unicode-категория `Cf` | Форматирующие Unicode-символы. |
| `ident-start-char` | `letter-char` или `_` | Первый символ обычного идентификатора. Цифра и апостроф в начале запрещены. |
| `ident-char` | буква, цифра, connecting, combining, formatting, `'` или `_` | Любой символ после первого. |
| `ident-text` | `ident-start-char ident-char*` | Полная форма обычного идентификатора. |

### Основные виды идентификаторов

| Вид | Лексическая форма | Примеры | Подробное описание |
|---|---|---|---|
| Обычный идентификатор | `ident-start-char ident-char*` | `x`, `_value`, `calculateSum`, `Person`, `value'`, `имя2` | Начинается с Unicode-буквы или `_`; далее разрешены буквы, цифры, `_`, `'` и перечисленные Unicode-категории. Не должен совпадать с ключевым или зарезервированным словом. |
| Backtick-идентификатор | Две обратные кавычки, непустое содержимое, две обратные кавычки | <code>``my value``</code>, <code>``type``</code>, <code>``value.with odd#name``</code> | Позволяет пробелы, ключевые слова и многие специальные символы. Внутри запрещены перевод строки, `\r`, табуляция и закрывающая пара двух обратных кавычек. |
| Квалифицированное имя | Несколько идентификаторов, разделённых `.` | `System.String`, `My.Module.value` | Не является одной лексемой: лексер возвращает идентификаторы и токены точки по отдельности. |
| Параметр обобщённого типа | `'` + имя | `'T`, `'Key` | Обычно токенизируется как апостроф и идентификатор либо специализированная грамматическая форма. Одинарная кавычка одновременно может открывать символьный литерал, поэтому требуется правило максимального совпадения и контекст. |
| Статически разрешаемый параметр типа | `^` + имя | `^T`, `^U` | Используется в inline-функциях и statically resolved type parameters. Это составная синтаксическая конструкция, а `^` также принадлежит алфавиту операторов. |
| Символический оператор как имя | Символическая последовательность, при объявлении обычно в `(...)` | `(>>=)`, `(.+.)`, `(+?)` | Допустимые операторные символы описаны в п. 1.4. Сам оператор является `SYMBOLIC_OPERATOR`, а скобки — отдельными токенами. |
| Активный шаблон | `(|` + части имени + `|)` | `(|Even|Odd|)`, `(|Int|_|)` | Составная синтаксическая конструкция. Имена вариантов являются идентификаторами; `(`, `|`, `_`, `)` — символические токены. |
| Подстановочный знак | `_` | `_` | Отдельное символическое ключевое слово: означает wildcard pattern или анонимный параметр типа. Не следует возвращать как обычный пользовательский идентификатор. |

### Ограничения backtick-идентификаторов в именах типов и модулей

Если backtick-идентификатор используется как имя типа, случая discriminated union, модуля или пространства имён, дополнительно запрещены следующие символы:

| Запрещённые символы | Причина |
|---|---|
| `.`, `+`, `$`, `&`, `[`, `]`, `/`, `\`, `*`, `"`, `` ` `` | Ограничение относится к синтаксически определённым именам типов/модулей. Сам лексер может сначала распознать backtick-идентификатор, а окончательную допустимость проверить на более поздней стадии. |

### Зарезервированные формы идентификаторов

| Форма | Примеры | Правило обработки |
|---|---|---|
| `ident-text!` | `value!`, `read!` | Форма зарезервирована, кроме известных symbolic keywords `let!`, `use!`, `do!`, `yield!`, `return!`, `match!`. Не следует разбивать без проверки на обычный идентификатор и `!`. |
| `ident-text#` | `value#`, `type#` | Форма зарезервирована спецификацией. Лексер должен выдавать специальный токен/ошибку зарезервированной формы. |

### Предопределённые идентификаторы с автоматической заменой

Лексически они похожи на обычные идентификаторы, но компилятор заменяет их значениями среды исходного файла.

| Идентификатор | Токен | Результат замены |
|---|---|---|
| `__SOURCE_DIRECTORY__` | `SOURCE_DIRECTORY_MACRO` | Полный путь к каталогу текущего исходного файла как строка. |
| `__SOURCE_FILE__` | `SOURCE_FILE_MACRO` | Имя текущего исходного файла как строка. |
| `__LINE__` | `LINE_MACRO` | Номер текущей строки с учётом директив `#line`. |

### Имена классов, функций и переменных

| Сущность | Лексическое правило | Принятое соглашение | Примеры |
|---|---|---|---|
| Класс, запись, union, enum, тип | Обычный или backtick-идентификатор | Обычно `PascalCase` | `Person`, `FileReader`, <code>``special type``</code> |
| Случай discriminated union | Идентификатор | Обычно `PascalCase` | `Some`, `None`, `Success`, `Error` |
| Функция/значение `let` | Идентификатор | Обычно `camelCase`; публичные значения иногда `PascalCase` | `calculateSum`, `readFile`, `MaxValue` |
| Параметр/локальная переменная | Идентификатор | Обычно `camelCase` | `fileName`, `currentValue` |
| Изменяемая переменная | То же правило, что у значения | Обычно `camelCase`; изменяемость задаётся `mutable`, а не формой имени | `let mutable counter = 0` |
| Член типа | Идентификатор | Обычно `PascalCase` для публичных членов | `Name`, `Read`, `Length` |
| Модуль/пространство имён | Обычный или допустимый backtick-идентификатор | Обычно `PascalCase`, части разделяются `.` | `MyCompany.Compiler.Lexer` |

> Соглашения `PascalCase`/`camelCase` не являются лексическими ограничениями. Например, `person`, `Person` и `PERSON` — три различных допустимых идентификатора: F# чувствителен к регистру.

## 1.3. Виды констант и правила их описания

### Целочисленные литералы без суффикса

| Вид | Лексическая форма | Примеры | Значение и ограничения |
|---|---|---|---|
| Десятичный | цифры с необязательными `_` между группами цифр | `0`, `34`, `123_456_789` | Без суффикса обычно имеет тип `int`/`int32`. `_` улучшает читаемость и не входит в значение. |
| Шестнадцатеричный | `0x` или `0X` + hex-цифры | `0xFF`, `0X22_1f`, `0xDEAD_BEEF` | Допустимы `0-9`, `a-f`, `A-F` и разделители `_`. |
| Восьмеричный | `0o` или `0O` + цифры `0-7` | `0o77`, `0O123_456` | Цифры `8` и `9` недопустимы. |
| Двоичный | `0b` или `0B` + цифры `0-1` | `0b1010`, `0B1111_0000` | Цифры кроме `0` и `1` недопустимы. |

### Суффиксы целочисленных литералов

Суффиксы чувствительны к регистру и входят в ту же лексему, что и число.

| Суффикс | Тип F#/.NET | Примеры | Токен |
|---|---|---|---|
| отсутствует | `int` / `int32` | `86`, `0x56` | `INT32_LITERAL` |
| `y` | `sbyte`, знаковое 8-битное | `86y`, `0b0101y` | `SBYTE_LITERAL` |
| `uy` | `byte`, беззнаковое 8-битное | `86uy`, `0xFFuy` | `BYTE_LITERAL` |
| `s` | `int16` | `86s`, `0x56s` | `INT16_LITERAL` |
| `us` | `uint16` | `86us`, `0x56us` | `UINT16_LITERAL` |
| `l` | `int32` | `86l` | `INT32_LITERAL` |
| `u`, `ul` | `uint32` | `86u`, `86ul` | `UINT32_LITERAL` |
| `n` | `nativeint` | `123n`, `0x2D3Fn` | `NATIVEINT_LITERAL` |
| `un` | `unativeint` | `123un`, `0x2D3Fun` | `UNATIVEINT_LITERAL` |
| `L` | `int64` | `86L`, `0x56L` | `INT64_LITERAL` |
| `UL`, `uL` | `uint64` | `86UL`, `86uL` | `UINT64_LITERAL` |
| `I` | `bigint` (`System.Numerics.BigInteger`) | `12345678901234567890I` | `BIGINT_LITERAL` |

Формальная спецификация также допускает класс `bignum` с суффиксами `Q`, `R`, `Z`, `I`, `N`, `G`. В прикладном лексере их можно распознавать как `BIGNUM_LITERAL`, после чего семантическая стадия определяет поддерживаемый тип; для обычного современного F# практически значим прежде всего `I`.

### Вещественные и десятичные литералы

| Вид | Лексическая форма | Примеры | Токен/тип |
|---|---|---|---|
| Дробный `float` | целая часть, `.`, необязательная дробная часть | `3.14`, `10.`, `0.5` | `FLOAT64_LITERAL`, тип `float`/`double` |
| Экспоненциальный `float` | число + `e`/`E` + необязательный знак + показатель | `2.3e32`, `2.3e+32`, `3e-4`, `1.0E10` | `FLOAT64_LITERAL` |
| `float32`/`single` | целый или вещественный литерал + `f`/`F` | `3.14f`, `3F`, `2.3e10F` | `FLOAT32_LITERAL` |
| Побитовая форма `float32` | hex-целое + `lf` | `0x00000000lf` | `FLOAT32_LITERAL`; задаёт IEEE 754 по битовому шаблону |
| Побитовая форма `float64` | hex-целое + `LF` | `0x0000000000000000LF` | `FLOAT64_LITERAL`; задаёт IEEE 754 по битовому шаблону |
| `decimal` | целый или вещественный литерал + `M`/`m` | `3.14M`, `100m` | `DECIMAL_LITERAL`, тип `decimal` |

### Особые правила числовой токенизации

| Случай | Правильная токенизация | Пояснение |
|---|---|---|
| `-3` | На первичном этапе `-` + `3`; затем допустимо объединение в отрицательный числовой токен | Минус является оператором. Формальная спецификация описывает постфильтрацию соседних токенов. |
| `+3` | `+` + `3` | Плюс обычно обрабатывается как префиксный оператор. |
| `a-b` | `IDENTIFIER`, `-`, `IDENTIFIER` | Это вычитание; минус не должен ошибочно присоединяться к правому идентификатору. |
| `1..10` | `INT_LITERAL(1)`, `RANGE(..)`, `INT_LITERAL(10)` | Специальная постфильтрация не позволяет правилу максимального совпадения принять `1.` за `float`. |
| число + произвольное имя | Зарезервированная/ошибочная числовая форма | Последовательности `(xint | float32 | float64) ident-char+` зарезервированы для будущих форматов литералов; их не следует молча делить на число и идентификатор. |
| `infinity`, `-infinity`, `infinityf`, `-infinityf` | идентификатор и, при наличии, отдельный знак | Семантически это специальные значения `float`/`float32`, но не отдельные числовые токены формальной грамматики. |

### Логические, нулевое и единичное значения

| Лексема | Токен | Значение |
|---|---|---|
| `true` | `BOOL_LITERAL(true)` | Истина типа `bool`. |
| `false` | `BOOL_LITERAL(false)` | Ложь типа `bool`. |
| `null` | `NULL_LITERAL` | Нулевая ссылка для типов, допускающих `null`. |
| `()` | `UNIT_VALUE` либо `LPAREN` + `RPAREN` | Единственное значение типа `unit`. Формальная лексическая спецификация включает `(` и `)` в symbolic keywords; объединять их в один токен — проектное решение лексера. |

### Символьные литералы

| Вид | Форма | Примеры | Описание |
|---|---|---|---|
| Unicode-символ | `'` + один допустимый символ/escape + `'` | `'a'`, `'Ж'`, `'1'` | Значение типа `char` (`System.Char`). |
| Символ с escape | `'` + escape + `'` | `'\n'`, `'\t'`, `'\\'`, `'\''`, `'\u0061'` | Escape преобразуется в один символ. |
| Byte-символ | символьный литерал + `B` | `'a'B`, `'\n'B` | Значение типа `byte`; содержимое должно укладываться в поддерживаемый однобайтовый диапазон. |

Недопустимы пустой символьный литерал, более одного результирующего символа, необработанный перевод строки, незакрытая кавычка и значение Unicode, не представимое одним `System.Char`.

### Управляющие последовательности строк и символов

| Последовательность | Значение | Где применяется |
|---|---|---|
| `\a` | Звуковой сигнал (alert) | Обычная строка и символ |
| `\b` | Backspace | Обычная строка и символ |
| `\f` | Перевод страницы | Обычная строка и символ |
| `\n` | Перевод строки | Обычная строка и символ |
| `\r` | Возврат каретки | Обычная строка и символ |
| `\t` | Горизонтальная табуляция | Обычная строка и символ |
| `\v` | Вертикальная табуляция | Обычная строка и символ |
| `\\` | Обратная косая черта | Обычная строка и символ |
| `\"` | Двойная кавычка | Прежде всего обычная строка |
| `\'` | Одинарная кавычка | Строка и символьный литерал |
| `\DDD` | Символ с десятичным кодом `000`–`255` | Обычная строка/символ; цифры трактуются как десятичные, не восьмеричные |
| `\xHH` | Символ с двухзначным hex-кодом | Обычная строка/символ |
| `\uHHHH` | Unicode-код UTF-16 из четырёх hex-цифр | Обычная строка/символ |
| `\U00HHHHHH` | Unicode-код UTF-32 из восьми hex-цифр | Обычная строка; результат может потребовать суррогатную пару |
| `\` + перевод строки + начальные пробелы следующей строки | Продолжение строки без добавления перевода и отступа | Обычная строка |
| `\` + иной символ | Неэкранирующая последовательность согласно формальной грамматике строки | В строке обратная косая черта может сохраняться вместе с символом; реализация должна следовать выбранной версии F# и отдельно выявлять реально ошибочные escape-последовательности |

### Строковые и байтовые литералы

| Вид | Ограничители/форма | Пример | Подробное описание |
|---|---|---|---|
| Обычная Unicode-строка | `"..."` | `"Hello\nWorld"` | Тип `string`. Обрабатывает escape-последовательности. По спецификации может содержать физический перевод строки. |
| Многострочная обычная строка | `"...` перевод строки `..."` | `"abc` + новая строка + `def"` | Физический перевод строки входит в значение, если перед ним нет escape-продолжения. |
| Verbatim-строка | `@"..."` | `@"C:\Users\Test"` | `\` не начинает escape. Двойная кавычка внутри записывается как `""`. Переводы строк допустимы. |
| Строка в тройных кавычках | `"""..."""` | `"""<tag a="1">"""` | Содержимое трактуется буквально; удобно для текста с кавычками и обратными косыми чертами. Закрывается последовательностью из трёх кавычек. |
| Byte-строка | `"..."B` | `"ABC\n"B` | Создаёт `byte[]`; применяются правила обычной строки, но символы должны быть допустимы для byte-литерала. |
| Verbatim byte-строка | `@"..."B` | `@"C:\TEMP"B` | Создаёт `byte[]`; обратные косые черты буквальны, кавычки удваиваются. |

### Интерполированные строки

Интерполированная строка содержит текстовые сегменты и «отверстия» с F#-выражениями. Для полноценного лексера это не обязательно один неделимый токен: практичная реализация использует отдельное стартовое состояние строки и временно возвращается к обычным правилам внутри интерполяции.

| Форма | Пример | Особенности |
|---|---|---|
| Обычная | `$"Value = {x}"` | Escape-последовательности действуют; `{expr}` содержит F#-выражение. |
| С форматированием | `$"Value = %0.2f{x}"` | Перед отверстием может находиться printf-подобный спецификатор формата. |
| Verbatim | `$@"Path: {root}\file"` | `\` буквален; выражения в `{...}` вычисляются. |
| Verbatim, обратный порядок префиксов | `@$"Path: {root}\file"` | Эквивалентная поддерживаемая форма. |
| Triple-quoted | `$"""Text {expr} "quoted""""` | Совмещает интерполяцию и тройные кавычки. |
| Расширенная raw-интерполяция | `$$"""Text {{expr}} and {literal braces}"""` | Число `$` задаёт число фигурных скобок, необходимое для открытия/закрытия интерполяции. Поддерживается современными версиями F# (начиная с F# 8). |

Правила фигурных скобок:

| Запись | Значение |
|---|---|
| `{expr}` | Интерполируемое выражение при одном `$`. |
| `{{` и `}}` | Литеральные одиночные скобки в обычной интерполированной строке. |
| При `n` символах `$` | Отверстие открывается и закрывается последовательностью из `n` фигурных скобок; более короткие последовательности можно использовать как обычный текст. |

### Константы времени компиляции `[<Literal>]`

| Конструкция | Лексический состав | Смысл |
|---|---|---|
| `[<Literal>] let Name = constant-expression` | `[<`, `IDENTIFIER(Literal)`, `>]`, `let`, имя, `=`, литеральное выражение | Объявляет именованную константу времени компиляции. Это не новый вид одного токена: атрибут, имя и выражение распознаются отдельно. |

## 1.4. Операции и другие синтаксические знаки

### Полный набор символических ключевых последовательностей

Эти последовательности имеют фиксированное синтаксическое значение и должны проверяться раньше общего правила пользовательского оператора.

| Лексемы | Токены/назначение |
|---|---|
| `let!`, `use!`, `do!`, `yield!`, `return!`, `match!` | Составные ключевые слова computation expressions. |
| `->`, `<-` | Стрелка результата/типа/ветви и оператор присваивания. |
| `.` | Доступ к члену, часть квалифицированного имени; отдельный токен. |
| `:` | Аннотация типа и другие контекстные роли. |
| `(`, `)` | Группировка, аргументы, кортежи, unit. |
| `[`, `]` | Списки, индексация и другие контекстные конструкции. |
| `[<`, `>]` | Начало и конец списка атрибутов. |
| `[|`, `|]` | Начало и конец массива. |
| `{`, `}` | Записи, объектные выражения, computation expressions и блоки. |
| `'` | Символьные литералы и параметры обобщённых типов; роль определяется контекстом/правилом максимального совпадения. |
| `#` | Директивы и flexible type. |
| `:?>`, `:?`, `:>` | Downcast, проверка типа и upcast. |
| `..` | Диапазон/срез. |
| `::` | Добавление элемента в начало списка и разбор списка в шаблоне. |
| `:=` | Устаревшее присваивание reference cell. |
| `;;` | Завершение фрагмента, главным образом в F# Interactive. |
| `;`, `,` | Разделители выражений/элементов и компонентов кортежа. |
| `=` | Равенство, связывание и разделитель в объявлениях — смысл контекстный. |
| `_` | Wildcard/анонимный параметр. |
| `?`, `??` | Необязательные аргументы, динамический поиск и зарезервированные контекстные формы. |
| `(*)` | Специальная фиксированная символическая последовательность формальной грамматики. |
| `<@`, `@>`, `<@@`, `@@>` | Границы типизированных и нетипизированных quotations. |

Последовательности `~` и одиночная обратная кавычка `` ` `` зарезервированы как символические последовательности для будущего использования. При этом `~` также может начинать общий символический оператор, поэтому точное решение зависит от полного совпадения и контекста.

### Арифметические и сравнительные операторы

| Лексема | Токен | Назначение |
|---|---|---|
| `+` | `OP_PLUS` | Бинарное сложение или унарный плюс. |
| `-` | `OP_MINUS` | Бинарное вычитание или унарное отрицание; участвует в постобработке отрицательных чисел. |
| `*` | `OP_MUL` | Умножение; в типах разделяет компоненты кортежа и используется в единицах измерения. |
| `/` | `OP_DIV` | Деление; применяется также в единицах измерения. |
| `%` | `OP_MOD` | Остаток от деления; внутри quotation может обозначать splice. |
| `**` | `OP_POWER` | Возведение в степень. |
| `=` | `OP_EQUAL_OR_EQUALS_SIGN` | Структурное равенство либо синтаксический разделитель определения/поля, в зависимости от контекста. |
| `<>` | `OP_NOT_EQUAL` | Структурное неравенство. |
| `<`, `<=` | `OP_LT`, `OP_LE` | Сравнение «меньше», «меньше либо равно». |
| `>`, `>=` | `OP_GT`, `OP_GE` | Сравнение «больше», «больше либо равно». |

### Логические и побитовые операторы

| Лексема | Токен | Назначение |
|---|---|---|
| `&&` | `OP_BOOL_AND` | Короткозамкнутое логическое И. |
| `||` | `OP_BOOL_OR` | Короткозамкнутое логическое ИЛИ. |
| `not` | `IDENTIFIER` | Стандартная функция логического отрицания, не символический оператор и не зарезервированное ключевое слово. |
| `&&&` | `OP_BIT_AND` | Побитовое И. |
| `|||` | `OP_BIT_OR` | Побитовое ИЛИ. |
| `^^^` | `OP_BIT_XOR` | Побитовое исключающее ИЛИ. |
| `~~~` | `OP_BIT_NOT` | Побитовое отрицание. |
| `<<<` | `OP_SHIFT_LEFT` | Побитовый сдвиг влево. |
| `>>>` | `OP_SHIFT_RIGHT` | Побитовый сдвиг вправо. |

### Функциональные операторы

| Лексема | Токен | Назначение |
|---|---|---|
| `|>` | `OP_PIPE_RIGHT` | Передаёт одно значение слева функции справа. |
| `||>` | `OP_PIPE2_RIGHT` | Передаёт функции справа кортеж из двух аргументов. |
| `|||>` | `OP_PIPE3_RIGHT` | Передаёт функции справа кортеж из трёх аргументов. |
| `<|` | `OP_PIPE_LEFT` | Передаёт выражение справа функции слева. |
| `<||` | `OP_PIPE2_LEFT` | Передаёт функции слева кортеж из двух аргументов. |
| `<|||` | `OP_PIPE3_LEFT` | Передаёт функции слева кортеж из трёх аргументов. |
| `>>` | `OP_COMPOSE_RIGHT` | Композиция функций слева направо. |
| `<<` | `OP_COMPOSE_LEFT` | Композиция функций справа налево. |
| `->` | `ARROW` | Отделяет параметры функции от тела, аргумент от результата в типе, шаблон от результата ветви. |

### Операторы коллекций, присваивания, типов и прочие стандартные формы

| Лексема | Токен | Назначение |
|---|---|---|
| `::` | `OP_CONS` | Добавляет элемент в голову списка; разбирает список на голову и хвост в шаблоне. |
| `@` | `OP_LIST_APPEND` | Конкатенирует списки. |
| `<-` | `OP_ASSIGN` | Присваивает новое значение mutable-переменной, полю, элементу массива/индексируемого объекта. |
| `!` | `OP_DEREF_OR_BANG` | Исторически разыменовывает reference cell; после ряда слов входит в computation-expression keyword. |
| `:=` | `OP_REF_ASSIGN` | Историческое присваивание reference cell; устаревающая форма. |
| `:>` | `OP_UPCAST` | Явное восходящее приведение. |
| `:?>` | `OP_DOWNCAST` | Явное нисходящее приведение. |
| `:?` | `OP_TYPE_TEST` | Проверяет значение на принадлежность типу. |
| `?` | `QUESTION`/`SYMBOLIC_OPERATOR` | Отмечает необязательный аргумент или динамический поиск. |
| `?<-` | `DYNAMIC_SET_OPERATOR` | Динамическая установка свойства; единственный специальный оператор, который наряду с `?` может начинаться с `?`. |
| `&` | `SYMBOLIC_OPERATOR` | AND-pattern либо получение адреса mutable-значения в interop-контексте. |
| `^` | `SYMBOLIC_OPERATOR` | Начало statically resolved type parameter; также стандартный оператор конкатенации строк. |
| `~-`, `~+`, `~~` | `SYMBOLIC_OPERATOR` | Имена перегружаемых унарных операторов: минус, плюс и отрицание. |
| `%`, `%%` | `SYMBOLIC_OPERATOR` | В quotations вставляют типизированное или нетипизированное выражение; вне них могут иметь операторное значение. |

### Nullable-операторы

Эти библиотечные/стандартные символические операторы сравнивают или вычисляют с nullable-операндом. Лексически все они удовлетворяют общему правилу `SYMBOLIC_OPERATOR`.

| Расположение nullable-операнда | Формы |
|---|---|
| Nullable слева | `?+`, `?-`, `?*`, `?/`, `?=`, `?<>`, `?<`, `?<=`, `?>`, `?>=` |
| Nullable справа | `+?`, `-?`, `*?`, `/?`, `=?`, `<>?`, `<?`, `<=?`, `>?`, `>=?` |
| Nullable с обеих сторон | `?+?`, `?-?`, `?*?`, `?/?`, `?=?`, `?<>?`, `?<?`, `?<=?`, `?>?`, `?>=?` |

> Не все формы, начинающиеся с `?`, соответствуют базовому правилу пользовательского `symbolic-op` из формальной главы; часть nullable-операторов является распознаваемой библиотечной/синтаксической формой. Поэтому известные многосимвольные операторы следует размещать перед общим правилом.

### Пользовательские символические операторы

| Компонент | Допустимые символы | Правило |
|---|---|---|
| Первый символ | `! % & * + - . / < = > @ ^ | ~` | Обязателен. |
| Последующие символы | те же символы, а также `?` и `:` | Могут повторяться ноль и более раз. |
| Специальные формы с `?` | только `?` и `?<-` по базовой формальной грамматике | Произвольный пользовательский оператор не может начинаться с `?`. |

Общая абстрактная форма:

```text
first-op-char = [!%&*+\-./<=>@^|~]
op-char       = [!%&*+\-./<=>@^|~?:]
symbolic-op   = "?" | "?<-" | first-op-char op-char*
```

Из общего совпадения необходимо исключить все фиксированные symbolic keywords (`->`, `<-`, `..`, `::`, `:=`, `<@` и т. д.), а также начала комментариев `//`, `(*` и их завершение `*)` в соответствующем состоянии.

### Разделители и составные ограничители

| Знаки | Назначение | Лексическая особенность |
|---|---|---|
| `(`, `)` | Группировка, вызов, кортеж, unit | Два соседних знака `()` семантически образуют unit. |
| `[`, `]` | Список, индекс/срез | Отдельные токены. |
| `[|`, `|]` | Массив | Фиксированные многосимвольные токены. |
| `{`, `}` | Запись, объектное выражение, computation expression | Отдельные токены. |
| `{|`, `|}` | Анонимная запись | Может обрабатываться как известные составные разделители либо как `{`/`|` и `|`/`}` с последующей синтаксической сборкой. |
| `[<`, `>]` | Атрибуты | Фиксированные символические ключевые слова. |
| `<@`, `@>` | Типизированная quotation | Фиксированные ограничители. |
| `<@@`, `@@>` | Нетипизированная quotation | Фиксированные ограничители. |
| `,` | Кортежи, параметры типов/методов | Отдельный токен. |
| `;` | Элементы списка/массива/записи, последовательность выражений | Отдельный токен. |
| `;;` | Завершение интерактивного фрагмента | Один фиксированный symbolic keyword, а не обязательно два `;`. |
| `.` | Доступ к члену/квалификация | Отличать от `..` и точки внутри вещественного числа. |
| `..` | Диапазон и срез | Отличать от двух точек и от окончания `float`. |
| `:` | Аннотация типа | Также допустим как последующий символ пользовательского оператора. |
| `|` | Ветвь `match`, случай union/enum, часть active pattern | Может одновременно принадлежать общему операторному алфавиту. |
| `_` | Wildcard | Фиксированный symbolic keyword. |
| `'` | Символ или параметр типа | Требует разрешения конкуренции правил. |
| `#` | Директива или flexible type | Значение зависит от позиции. |

### Директивы и служебные лексемы

| Конструкция | Токенизация | Назначение |
|---|---|---|
| `#if условие` | `IF_DIRECTIVE` и выражение директивы | Начинает условно компилируемый участок. Директива занимает отдельную строку. |
| `#else` | `ELSE_DIRECTIVE` | Альтернативная ветвь условной компиляции. |
| `#endif` | `ENDIF_DIRECTIVE` | Завершает условную компиляцию. Вложенность разрешена. |
| `#line N` / `# N` | `LINE_DIRECTIVE` | Меняет логический номер следующей строки. |
| `#line N "file"` / `# N @"file"` | `LINE_DIRECTIVE` | Меняет логические номер строки и имя файла для диагностики/отладки. |
| `#nowarn`, `#light` | `#` + идентификатор + аргументы либо специализированная директива | Компиляторные директивы; формальная лексическая глава отдельно фиксирует только условные и line-директивы, остальные могут разбираться последующей стадией. |
| `#r`, `#load`, `#I`, `#time`, `#help`, `#quit` | Директивные формы F# Interactive/скриптов | Значимы прежде всего в `.fsx`/FSI. Лексер может иметь отдельные токены или общий `HASH_DIRECTIVE`. |

Условия `#if` используют идентификаторы, `!`, `&&`, `||` и круглые скобки. Пробелы перед `#` разрешены, между `#` и именем директивы — нет. Строка условной директивы может оканчиваться пробелами и однострочным комментарием; многострочный комментарий на этой строке не допускается.

### Пробельные и скрытые элементы

| Элемент | Форма | Обработка |
|---|---|---|
| Пробелы | один или несколько пробелов | Обычно отбрасываются, но позиции сохраняются для диагностики. |
| Перевод строки | `\n` или `\r\n` | Первичный лексер распознаёт; F#-фильтр значимого отступа использует строки/колонки для offside rule. |
| Табуляция | символ табуляции | В исходном коде влияет на позицию; внутри backtick-идентификатора запрещена. Реализации следует нормализовать подсчёт колонок согласованно. |
| Скрытые токены | Не присутствуют буквально в файле | Вставляются стадией lexical filtering для отступов, балансировки и контекстной грамматики; их не надо искать регулярными выражениями во входном тексте. |

## 1.5. Способы задания комментариев

### Таблица комментариев

| Вид | Начало | Конец | Токен | Подробные правила |
|---|---|---|---|---|
| Однострочный | `//` | Перед `\n`, `\r\n` или EOF | `LINE_COMMENT` | Всё после `//` до конца физической строки является комментарием. Обычно токен отбрасывается. |
| XML-документация | `///` | Перед переводом строки или EOF | `XML_DOC_COMMENT` | Специальный однострочный комментарий, связанный со следующим объявлением для генерации XML-документации. Если документация не нужна, допустимо обрабатывать как `LINE_COMMENT`, но информация будет потеряна. |
| Блочный | `(*` | Соответствующий `*)` | `BLOCK_COMMENT` | Может занимать несколько строк и **может быть вложенным**. Нужен счётчик глубины либо стек состояний. |
| Shebang | `#!` только в начале файла | До конца первой строки | `SHEBANG_COMMENT` | Позволяет `.fsx`-скрипту указывать Unix-интерпретатор, например `#!/usr/bin/env -S dotnet fsi`. Рассматривается как комментарий. |

### Правила вложенного блочного комментария

| Событие внутри состояния комментария | Действие лексера |
|---|---|
| Встречено `(*` | Увеличить глубину вложенности на 1. |
| Встречено `*)` | Уменьшить глубину; при достижении 0 выйти в исходное состояние. |
| Встречена строка `"..."`, `@"..."` или `"""..."""` | Распознать строку целиком по её правилам. Последовательность `*)` внутри такой строки не завершает комментарий. |
| Встречен перевод строки | Увеличить счётчик строк и продолжить комментарий. |
| Достигнут EOF при глубине больше 0 | Выдать ошибку `UNCLOSED_BLOCK_COMMENT` с позицией открывающего `(*`. |

Корректный пример:

```fsharp
(*
   Внешний комментарий.
   (* Вложенный комментарий. *)
   Строка "*)" не закрывает внешний комментарий.
*)
```

### Приоритет правил комментариев

| Конфликт | Правильное решение |
|---|---|
| `/` и `//` | Сначала проверять `//`, затем общий символический оператор `/...`. |
| `(` + `*` и `(*` | Сначала проверять начало комментария `(*`; иначе получится `LPAREN` + `OP_MUL`. |
| `*` + `)` вне комментария | В исходном состоянии это не конец комментария; может быть оператор `*` и `RPAREN` либо диагностическая ошибка по решению грамматики. |
| `///` и `//` | Если XML-документацию нужно сохранять отдельно, правило `///` должно стоять раньше `//`. |
| `#!` и `#` | Shebang распознаётся только в позиции 0/в начале файла; в остальных местах применяются правила директив/символа `#`. |

## Критические правила порядка распознавания

1. Комментарии, строки и директивы распознаются до общего правила символических операторов.
2. Самые длинные фиксированные последовательности проверяются раньше коротких: например, `<@@` раньше `<@`, `:?>` раньше `:?`/`:>`, `|||>` раньше `||>`/`|>`, `>>>` раньше `>>`/`>`.
3. Ключевые слова отличаются от начала идентификатора правилом максимального совпадения: `whileValue` — один `IDENTIFIER`, а не `KW_WHILE` + `IDENTIFIER`.
4. `let!`, `use!`, `do!`, `yield!`, `return!`, `match!` проверяются как цельные symbolic keywords.
5. После распознавания обычного `ident-text` выполняется проверка таблиц: действующие ключевые слова, зарезервированные слова, специальные заменяемые идентификаторы, затем обычный `IDENTIFIER`.
6. Число с суффиксом распознаётся целиком; неверный хвост после числа не должен незаметно превращаться в отдельный идентификатор.
7. Для `1..10` применяется специальное правило: целое `1`, диапазон `..`, целое `10`.
8. Блочные комментарии требуют состояния и счётчика вложенности; простого регулярного выражения до первого `*)` недостаточно.
9. Интерполированные строки требуют состояний и контроля фигурных скобок; выражения внутри отверстий снова лексируются как F#-код.
10. Лексер должен работать с UTF-8 и корректно определять Unicode-категории символов идентификатора.

## Минимальный набор диагностируемых лексических ошибок

| Ошибка | Пример | Требуемая реакция |
|---|---|---|
| Незакрытая обычная строка | `"text` | Сообщить позицию открывающей кавычки и состояние строки. |
| Незакрытая verbatim/triple-quoted строка | `@"text`, `"""text` | Сообщить конкретный вид строки. |
| Незакрытая интерполяция | `$"x={value"` | Сообщить незакрытое отверстие или строку. |
| Незакрытый символ | `'a` | Сообщить ошибку символьного литерала. |
| Пустой/многосимвольный char | `''`, `'ab'` | Сообщить, что требуется ровно один результирующий `char`. |
| Неверная escape-последовательность/код | `'\uZZZZ'` | Сообщить вид escape и позицию. |
| Недопустимая цифра основания | `0b102`, `0o89` | Не делить молча на корректный префикс и остаток; сообщить ошибку числа. |
| Неверный/зарезервированный числовой хвост | `123abc` | Сообщить зарезервированную/недопустимую числовую форму. |
| Выход числа за диапазон суффикса | `300uy` | Лексер или семантическая стадия сообщает переполнение `byte`. |
