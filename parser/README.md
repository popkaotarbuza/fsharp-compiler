# Парсер учебного F# на GNU Bison

## Организация

Парсер организован по примеру [brookite/vb_compiler](https://github.com/brookite/vb_compiler): `%token`, `%union`, `%type`, правила с семантическими действиями, обработчики создания AST и общий корень программы.

Интерфейс обычный, как в примере:

```cpp
int yyparse();
int yylex();
void yyerror(const char* message);

extern fsharp::Node* program;
extern bool hasSyntaxErrors;
```

Глобальные `yylval` и `yylloc` создаёт Bison. `yyin`, `yytext` и `yylineno` предоставляет Flex. Тестового раннера, `runParserTests`, адаптера массивов токенов и собственного `main` в парсере нет.

| Файл | Назначение |
|---|---|
| `grammar.y` | Терминалы, нетерминалы и синтаксические правила. |
| `nodes.hpp` | Виды узлов, позиции, флаги и владение AST. |
| `grammar_handler.hpp` | Объявления обработчиков. |
| `grammar_handler.cpp` | Создание узлов и текстовый вывод дерева. |
| `examples/*.fs` | Иллюстрации поддерживаемого учебного синтаксиса, не автоматические тесты. |

Обработчик компилируется отдельным `.cpp`, а не включается в грамматику через `#include "grammar_handler.cpp"`: так не возникает повторных определений.

## Статус Подключения

Правила и AST написаны, но существующий лексер **ещё не подключён к Bison**. Он только печатает лексемы и имеет собственный `main`. Для совместного разбора нужно возвращать токены из `yylex()`, заполнять `yylval` и `yylloc`, вызывать `yyparse()` из точки входа и добавить фильтр границ блоков.

Текущая конфигурация Visual Studio по-прежнему собирает отдельный лексер. Генерация Bison, сборка и запуск не выполнялись; число конфликтов грамматики не установлено. Наличие правил не означает, что реализованы семантический анализ, генерация кода и полный промышленный F#.

## Покрытие Карточки

Таблица отражает написанные синтаксические правила, а не результаты выполненных проверок.

| Требование | Правила и AST |
|---|---|
| Локальные значения `int`, `char`, `string` | `binding`, `binding_group`, `sequence_expr`, литералы и аннотации типов. |
| Изменяемость | `let mutable`, узел `Assignment` для `<-`; проверка допустимости изменения выполняется семантически. |
| Арифметические выражения | Унарные знаки, `+`, `-`, `*`, `/`, `%`, сравнения и группировка скобками. |
| Одномерные массивы | `[| ... |]`, пустые массивы, тип `int[]`, доступ `array.[i]` и присваивание элементу. |
| Списки и последовательности | `[ ... ]`, `::`, диапазоны, ограниченная форма `seq { ... }`, `yield` и `yield!`. |
| Условия | `if`, `elif`, `else`, вариант без `else`, `match`, guards `when`. |
| Циклы | `while`, `for ... to`, `for ... downto`, `for ... in`; подробная форма с `done`. |
| Функции | Параметры, каррированное применение, кортежные аргументы, `fun`, `function`, `let rec` и `and`. |
| Консольный ввод и вывод | Обычное применение `printf`/`printfn` и доступ к `System.Console.Write`, `WriteLine`, `ReadLine`. Эти имена не превращаются в ключевые слова. |
| Классы и наследование | `type`, первичный конструктор, поля, `member`, `inherit`, `abstract member`, `default`, `override`, `base`, ограниченные интерфейсы. |
| Свойства | `member _.Name = ...`, `with get ... and set ...`, абстрактные сигнатуры `with get, set`. |
| Методы и перегрузка | Каждый метод с параметрами и аннотациями создаёт отдельный узел; выбор перегрузки выполняется после разбора. |
| Плавающая точка | `FLOAT32_LITERAL`, `FLOAT64_LITERAL`, `DECIMAL_LITERAL`, аннотации и обычные операции. |
| Логические операции | `&&`, `||`, `true`, `false`; `not x` является применением функции. |
| Контроль доступа | `private`, `public`, `internal`; флаги сохраняются в AST. |
| Конструкторы и ресурсы | `new`, дополнительные конструкторы с `then`, `use`, `use!`, реализация `IDisposable` через правила интерфейса. |
| Перечисления | Варианты `| Name = 0`, в том числе отрицательные целые значения. |
| Исключения | `exception`, `try ... with`, `try ... finally`; `raise` и `failwith` являются обычными именами функций. |

## Охват Лексем

Все реальные токены сохраняют названия из `lexer/fsharp_lexer.l`. Они используются в правилах либо явно обрабатываются как зарезервированные. Пунктуация остаётся именованными токенами: `OP_PLUS`, `LPAREN`, `SEMICOLON`, а не кодами символов `'+'`, `'('`, `';'`.

| Токены | Где используются |
|---|---|
| `KW_LET`, `KW_REC`, `KW_MUTABLE`, `KW_INLINE`, `KW_AND` | Связывания, рекурсивные группы, модификаторы и методы доступа через `and`. |
| `KW_PRIVATE`, `KW_PUBLIC`, `KW_INTERNAL` | Модификаторы объявлений, членов и типов. |
| `KW_OPEN`, `KW_MODULE`, `KW_NAMESPACE`, `KW_GLOBAL` | Открытие имён, заголовки и вложенные модули, глобальные квалифицированные имена. |
| `KW_IF`, `KW_THEN`, `KW_ELIF`, `KW_ELSE` | Условия и дополнительное тело конструктора после `then`. |
| `KW_FUN`, `KW_FUNCTION`, `KW_MATCH`, `KW_WITH`, `KW_WHEN` | Лямбды, сопоставление и свойства. |
| `KW_FOR`, `KW_IN`, `KW_TO`, `KW_DOWNTO`, `KW_WHILE`, `KW_DO`, `KW_DONE` | Циклы, локальное `in`, выражения `do`. |
| `KW_TYPE`, `KW_OF`, `KW_CLASS`, `KW_STRUCT`, `KW_END` | Определения типов, объединения, явные классы и структуры. |
| `KW_MEMBER`, `KW_ABSTRACT`, `KW_DEFAULT`, `KW_OVERRIDE`, `KW_STATIC`, `KW_VAL` | Методы, сигнатуры, статические связывания и поля. |
| `KW_NEW`, `KW_AS`, `KW_INHERIT`, `KW_INTERFACE`, `KW_BASE` | Конструкторы, имя текущего экземпляра, наследование, интерфейсы и базовый объект. |
| `KW_EXCEPTION`, `KW_TRY`, `KW_FINALLY` | Объявления и обработка исключений. |
| `KW_USE`, `KW_USE_BANG`, `KW_YIELD`, `KW_YIELD_BANG`, `KW_RETURN`, `KW_RETURN_BANG`, `KW_SELECT` | Ресурсы и ограниченные вычислительные выражения; `select` сохраняется как узел проекции. |
| `KW_ASSERT`, `KW_LAZY`, `KW_UPCAST`, `KW_DOWNCAST`, `KW_FIXED` | Унарные формы. Допустимость `fixed` проверяется в контексте ресурса. |
| `KW_EXTERN`, `KW_DELEGATE`, `KW_VOID` | Внешние сигнатуры, тип делегата и имя возвращаемого типа. Атрибуты P/Invoke не добавлены. |
| `KW_BEGIN`, `KW_END` | Явная группировка последовательности. |
| `KW_OR` | Явная диагностика зарезервированного слова совместимости с ML. Это не альтернативная запись `||`. |
| `IDENTIFIER`, `WILDCARD` | Имена, параметры, образцы и `_`. |
| Все литеральные токены, `BOOL_TRUE`, `BOOL_FALSE`, `KW_NULL` | Литералы выражений и образцов. |
| Все `OP_*` текущего лексера | Арифметика, сравнения, логика, присваивание и `::`. |
| `ARROW`, `DOT`, `RANGE`, `COLON`, `COMMA`, `SEMICOLON`, `BAR` | Функции, типы, члены, диапазоны, кортежи, коллекции и ветви. |
| Все скобки | Группировка, параметры, списки, массивы, определения записей и вычислительные выражения. |
| Все `INTERP_*` | Интерполированная строка, её текст и вложенные выражения. |
| `NEWLINE` | Допустимые пустые переводы строк на границе объявлений. Значимые границы тел определяет фильтр, а не этот токен сам по себе. |

Нельзя добавлять правило, которое превращает любое ключевое слово в имя только для формального охвата токенов: это допустило бы ошибочные F#-программы. Для `or` выбран явный отказ с объяснением.

## Значения Токенов

В `%union` используются строки, указатели на узлы и флаги. Для `IDENTIFIER`, числовых, строковых и символьных литералов и `INTERP_TEXT` нужно заполнить `yylval.text`:

```cpp
yylval.text = new std::string(yytext, yyleng);
return IDENTIFIER;
```

Числовые литералы передаются исходной записью с суффиксом, без потери точности при преобразовании в машинный тип. Строки и символы передаются **после декодирования** поддерживаемых escape-последовательностей, а не вместе с кавычками. Лексер сохраняет Unicode и регистр имён.

Знаки и ключевые слова без строкового значения возвращаются напрямую:

```cpp
return KW_LET;
return OP_PLUS;
```

Для `%locations` лексер должен заполнять `yylloc.first_line`, `first_column`, `last_line`, `last_column`. Одного `%option yylineno` недостаточно для столбцов. Позиции виртуальных токенов привязываются к соответствующим реальным границам.

Вывод `printf("KW_LET: ...")` не заменяет `return KW_LET`. Текстовый отчёт лексера нельзя надёжно использовать как вход Bison: значения строк и управляющие символы делают его многострочным.

## Отступы и Блоки

В VB из примера есть `End If`, `End Function`, `Next`. В обычном F# таких окончаний нет. Поэтому контракт из предоставленного проекта правил сохраняется:

| Виртуальные токены | Назначение |
|---|---|
| `BODY_BEGIN`, `BODY_END` | Границы тела binding, ветви, функции, цикла и `try`. |
| `SEQ_SEP` | Разделитель выражений и локальных связываний в теле. |
| `DECL_END` | Конец объявления верхнего уровня или члена класса. |
| `CASES_BEGIN`, `CASES_END` | Границы ветвей `match`, `function`, `try ... with`. |
| `TYPE_BEGIN`, `TYPE_END` | Границы определения типа, вложенного модуля, реализации интерфейса или методов доступа. |
| `TYPE_SEP` | Разделитель полей определения записи. |

Это не лексемы, которые пользователь пишет в `.fs`. Их создаёт контекстный фильтр. Он должен учитывать скобки, контекст, отступы, комментарии, пустые строки и завершение файла. Для однострочных тел границы тоже обязательны.

Например:

```fsharp
let add x y = x + y
```

Нормализованный поток:

```text
KW_LET IDENTIFIER(add) IDENTIFIER(x) IDENTIFIER(y) OP_EQUAL_OR_EQUALS_SIGN
BODY_BEGIN IDENTIFIER(x) OP_PLUS IDENTIFIER(y) BODY_END DECL_END
```

Для `if` каждое тело обрамляется отдельно. `BODY_END` then-ветви идёт **перед** `KW_ELSE`/`KW_ELIF`. Для `match` каждое тело после `ARROW` закрывается перед следующим `BAR`. Для `done` тело цикла закрывается перед `KW_DONE`.

Для определения типа после `=` нужен `TYPE_BEGIN`, затем содержимое, `TYPE_END` и внешний `DECL_END`. Каждый член класса дополнительно заканчивается собственным `DECL_END`. Вложенный модуль с `=` аналогично содержит список объявлений между `TYPE_BEGIN`/`TYPE_END`.

Локальное `let` в теле нормализуется как binding с собственными границами тела, затем `SEQ_SEP` и оставшаяся последовательность. Последовательность создаёт узел области видимости `LocalBinding`.

Внутри `[ ... ]` и `[| ... |]` разделитель остаётся `SEMICOLON`. Между полями определения записи используется `TYPE_SEP`. В `seq { ... }` и `query { ... }` внутренние элементы разделяются `SEQ_SEP`, а внешние скобки остаются `LBRACE`/`RBRACE`. Границы цикла внутри построителя должны отделять его тело от следующего `yield` или `select`.

Копирование VB-правил с заменой `End If` только на `NEWLINE` не решает обработку F#-отступов. Без фильтра нынешний лексер не может сформировать поток, ожидаемый этой грамматикой.

## AST

Синтаксические действия создают `Node` с видом, значением, флагами, позицией и упорядоченными дочерними узлами. Объявления, выражения, образцы и типы имеют разные `NodeKind`.

| Узел | Дочерние узлы |
|---|---|
| `Program` | Список объявлений. |
| `BindingGroup` | Список bindings; `Recursive` хранится на группе. |
| `Binding` | Параметры, тип результата или `null`, тело. |
| `Apply`, `Binary`, `Assignment` | Операнды; у диапазона с шагом три компонента. |
| `If` | Условие, then-ветвь, else-ветвь или `null`. |
| `LocalBinding` | Связывание и оставшаяся часть тела. |
| `MatchCase` | Образец, guard или `null`, тело. |
| `TypeDeclaration` | Параметры конструктора или `null`, описание типа. |
| `Member` | Параметры, тип результата или `null`, тело или методы доступа. |
| `AbstractMember` | Тип сигнатуры и методы доступа либо `null`. |
| `ForRange` | Начальная и конечная границы, тело; имя в `value`, `Descending` для `downto`. |
| `ExternDeclaration` | Возвращаемый тип и параметры. |
| `InterpolatedString` | Список текстовых сегментов и выражений. |

`f x y` создаёт `Apply(Apply(f, x), y)`, а `f (x, y)` — один `Apply` с кортежем. Скобки и `begin/end` сохраняют вложенность кортежей. Литералы хранят метку вида, например `int:42`, `string:Hello`, `bool:true`.

Арена `unique_ptr<Node>` владеет всеми узлами. `program` не владеет памятью и действителен до следующего разбора или завершения процесса. Строки успешно свёрнутых токенов забирают обработчики; отброшенные строки освобождает `%destructor`.

В `yyerror` устанавливается `hasSyntaxErrors`, сохраняется диагностика и очищается корень. В отличие от референса, ошибка **не вызывает `yyrestart` посреди разбора и не завершает процесс через `exit`**. Код `yyparse()` и флаг ошибки проверяет вызывающая программа. Отдельных правил восстановления через `error` пока нет.

Трассировка включена через `%define parse.trace`; во время запуска её можно включить присваиванием `yydebug = 1`. Собственные `parser_print` в каждом правиле не обязательны: Bison уже выводит сдвиги и свёртки.

## Границы Подмножества

- Синтаксическое покрытие карточки не заменяет проверку областей видимости, типов, перегрузок, наследования, изменяемости и освобождения ресурсов.
- Полный offside-синтаксис F# и контекстный фильтр ещё не реализованы.
- Для управляющих выражений в операндной позиции требуются скобки: `f (if p then a else b)` и `List.map (fun x -> x + 1) xs`.
- Отрицательный аргумент записывается `f (-1)`; `f - 1` разбирается как вычитание.
- `get` и `set` остаются `IDENTIFIER`, но правила свойства проверяют их текст. Имена построителей и допустимость `yield`/`return`/`select` проверяются семантически.
- `or` отвергается как слово совместимости с ML; поддержка старых ML-форм и специальных ограничений типов не заявлена.
- Обобщения, type variables, constraints, SRTP, active patterns, пользовательские операторы, полные object expressions и запросы LINQ не реализованы.
- Создание/обновление записей, генераторы коллекций `[for ... -> ...]`, современная индексация `a[i]`, OR/AND/as-образцы и завершающий `;` коллекции не описаны.
- Для стрелочного типа поля объединения нужны скобки: `| Handler of (int -> int)`.
- Дословные, тройные, байтовые строки, удалённые escape, pipe-операторы, степень, атрибуты, директивы и escaped-идентификаторы не добавлены: их нет в текущем учебном лексере.
- `extern` описывает сигнатуру, но не привязку к внешней библиотеке. Атрибуты и генерация P/Invoke отсутствуют.

## Генерация и Подключение

Из корня проекта, используя GNU Bison 3.6+ или соответствующий WinFlexBison:

```powershell
win_bison -Wall -Wcounterexamples -v --defines=parser/grammar.tab.h -o parser/grammar.tab.cpp parser/grammar.y
```

Для обычного GNU Bison команда называется `bison`. `win_bison` в проект пока не добавлен. Если сборка не поддерживает `-Wcounterexamples`, опцию можно убрать, сохранив предупреждения и отчёт `parser/grammar.output`.

Сгенерированный `grammar.tab.h` подключается лексером. Затем генерируется Flex и совместно компилируются:

```text
parser/grammar.tab.cpp
parser/grammar_handler.cpp
lexer/lex.yy.cpp
точка входа, вызывающая yyparse()
реализация фильтра границ блоков
```

При этом у программы должна быть одна точка входа, а не одновременно самостоятельный `main` лексера и новый `main` компилятора.

Перед использованием нужно разобрать все предупреждения и конфликты Bison. `%expect` и GLR не применены для их сокрытия. После подключения вызывающая программа должна проверять `yyparse() != 0`, `hasSyntaxErrors` и наличие лексических ошибок до обращения к `program`.
